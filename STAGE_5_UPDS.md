# Billing Control v2 — этап 5: УПД

Дата: 28.07.2026

## Что добавлено

- У каждого счёта в раскрытой карточке есть отдельная строка УПД.
- В строке показываются номер счёта, номер УПД, сумма счёта, дата УПД,
  дата отправки и дата подписания.
- В режиме редактирования номер УПД и три даты можно заполнить или изменить.
- Сумма УПД берётся из связанного счёта и не дублируется отдельным ручным
  полем.
- Дата УПД синхронизирована с `invoices.shipment_date`.
- Номер и даты сохраняются атомарно через `save_invoice_upd`.
- В клиентском режиме элементы редактирования отсутствуют.

## Существующие записи

До миграции заполненных УПД не было. В `upds` находились 197 полностью
пустых технических строк, а два новых счёта ещё не имели такой строки.

После миграции:

- счетов — 199;
- строк УПД, доступных для заполнения, — 199;
- счетов без строки УПД — 0;
- нескольких УПД у одного счёта — 0;
- заполненных УПД — 0.

Номера и даты не создавались автоматически, потому что их нельзя достоверно
восстановить из имеющихся данных.

## Новые счета

Триггер `sync_invoice_upd_after_write` автоматически создаёт одну строку УПД
после добавления нового счёта. Уникальное ограничение на `upds.invoice_id`
не допускает несколько УПД у одного счёта.

## Миграция

Миграция `stage_5_invoice_upds_all_existing` применена к рабочей Supabase.
Функции работают как `SECURITY INVOKER`, используют пустой `search_path` и
доступны для прямого вызова только `service_role`.

## Проверка

- Пройдены 63 автоматических теста.
- Подтверждено соответствие «один счёт — одна строка УПД».
- Существующие счета, суммы, платежи, приложения, периоды и фотоотчёты
  миграцией не изменялись.
